# 2026-04-22 — Round 1 (FileHeader) + Round 2 (DocInfo primitives) 완료

## 맥락

어제 strangler-fig 기반 라운드트립 하네스가 2개 fixture에 대해 바이트
동일성을 확보한 상태. 이제 `unknown_streams` 통과 중인 스트림을 하나씩
타입드 IR로 이주시키는 Rounds 작업 시작.

## Round 1 — `/FileHeader` 타입드 인코더

- `/FileHeader` 는 256 B 고정, 비압축. HWP5 스펙의 가장 단순한 스트림이라
  첫 타입드 슬라이스로 적합.
- **IR 변경**: `FileHeader { signature, version, flags, reserved: Vec<u8> }`.
  기존의 파생 bool 필드(`compressed`, `encrypted`, `distribute_doc`)를
  메서드로 이동 (플래그 비트가 단일 source of truth가 되도록).
  `reserved: Vec<u8>(216)` 에 bytes 40..256 verbatim 보관.
- **Reader / Writer**: `/FileHeader` 는 이제 `unknown_streams` 우회,
  `streams::file_header::{parse, emit}` 로 라운드트립.
- **테스트 결과**: 3 round-trip + 7 core = 10/10 green. fixture 두 개
  모두 바이트 동일 유지.

## Round 2 — DocInfo 원시 primitives

DocInfo/BodyText 스트림은 zlib-wrapped이 아니라 **raw DEFLATE (RFC 1951)**
로 압축되어 있음 (hwplib 의 `Deflater(level, nowrap=true)`와 동일).
이를 확인하기 위해 먼저 Reader/Writer에 **wire 하지 않고** primitive 만
랜딩:

- `streams::record`: HWP5 TLV 코덱. 헤더 packing:
  ```
  bits  0..10   tag
  bits 10..20   level
  bits 20..32   size   (== 0xFFF 이면 다음 u32 LE가 실제 size)
  ```
  `parse_all / emit_all / parse_one / emit_one` + 6 unit tests
  (소/대형/경계/다중/헤더 truncate/payload truncate).

- `streams::doc_info`: flate2 raw DEFLATE 래퍼 + `parse / emit = decompress
  + record::parse_all` 과 역방향. 태그 상수 15개 (DocumentProperties,
  IdMappings, BinData, FaceName, BorderFill, CharShape, TabDef, Numbering,
  Bullet, ParaShape, Style, DocData, DistributeDocData, CompatibleDocument,
  LayoutCompatibility).

- **실제 fixture 검증**: `real_docinfo_decompresses_and_parses` — 빈
  HWP fixture의 `/DocInfo` 를 decompress + parse. ParaShape 약 12개 +
  Style 약 20개 + 기타 기대한 태그 + **미지 태그 두 개**: `0x0020`,
  `0x005E`. 이들은 Round 3 (타입드 추출) 에서 hwplib 코드와 대조 필요.

- Reader/Writer wiring은 의도적으로 보류. Round 3에서 verbatim-
  passthrough-if-unchanged 전략 확정 후 이주.

## 발견 — 압축 바이트 비결정성

- flate2 (miniz_oxide 백엔드) 는 동일 입력에 대해 동일 출력을 내지만,
  **hwplib (Java java.util.zip) 출력과 byte-equal 보장은 없음**. 즉
  `HwpReader → HwpWriter` 재압축 시 fixture 와 raw bytes 레벨 동일성은
  깨짐.
- 해결 전략 (Round 3 에서 확정 예정):
  1. Reader가 DocInfo를 decompress 해 records를 파싱하되, **원본 압축
     바이트를 verbatim 필드에 별도 보관**.
  2. Writer는 records 가 read 이후 mutate 되지 않았으면 verbatim bytes
     를 그대로 emit. Mutate 되었으면 재압축.
  3. "mutate 여부"는 explicit dirty flag 혹은 records 해시 비교로.
- 이 방식이면 read-only 문서는 byte-equal 유지 + typed 접근 가능.

## 결과

- 현재 테스트 집합: **19/19 green** (8 unit + 4 integration + 7 core).
- `flate2 = "1.0"` workspace dep 추가.
- record.rs 를 곧 BodyText/Section{N} 파싱에도 재사용 (같은 TLV).

## 미해결 질문

- **Tag 0x0020, 0x005E 정체** — hwplib 의 `DocInfoTagEnum` 확인 필요.
  0x0020 은 아마 `TRACKCHANGE` 계열, 0x005E 는 TRL-specific 확장일 가능성.
- **Dirty 추적 디자인** — explicit flag vs content hash. Records vector
  만 있으면 hash 가 단순하지만 mutations 이 부분적일 때 재압축 비용이 큼.
- **Round 3 에 DocInfo 전체를 한번에 결선할지, 한 태그 타입씩(FontFace)
  결선할지** — 실용적으로는 한번에 records 벡터까지 모두 IR에 붙이고,
  typed 변환은 그 위에서 태그별로 진행하는 게 깔끔.
